Know Your Limitations

I’m never going to be the guy who remembers to manually update a hardcoded “last updated” field. I’m just not him.

Still, I kept hardcoding that field anyway, like someday I’d automate it.

That day has finally come.

Why I needed a CMS

I’ve been brushing up on SEO, accessibility, and semantic HTML—trying to make my content more portable and future-proof. This shift started while I was building the landing page for one of my projects, Abracadabra Sports.

Building a business isn’t the same as building a tool. Unexpectedly, I'm producing way more text than I ever planned.

The system is dead simple. It's a form to produce a JSON file with metadata for SEO and archival purposes. A FastAPI service with Jinja2 templating transforms the JSON into HTML, automatically updating metatags like the article's <h1> and <title> tags.

The content is created in a JavaScript WYSIWYG editor. Adding new sections, text, lists, and headings, plus reordering, is all done through the sidebar. If I really wanted to go all out, I’d bring that functionality into the preview window and kill the sidebar entirely.

The Feature Set: What I wanted to build

To be frank, I didn't do any research before starting this project. I didn't know, and still don't, what's being used at the Wall Street Journal or the New York Times, but it was safe to assume they aren’t raw-dogging HTML in Notepad.

Metadata management
Title, description, publish date, canonical URL, etc.
No-Code editing
Point-and-click editing, drag-and-drop reordering.
Publication pipeline
Rendering logic that converts JSON to clean HTML on the server.
Preview window
Because I like seeing what I’m writing.
Mobile friendly
Because why not?

Remarks

The repo will be available on my Git server (not this site) once I’ve finished the server-side publishing pipeline and added health checks for dead links and broken images.

Was it worth it?

It shouldn’t have been.

This started as a side project, and I wouldn’t call it core to any of my businesses. One of my other projects is the other kind of CMS—it has Customer Management System features, where promotional emails and public-facing pages are driven by actual customer needs.

Will this ever become a product?

Probably not.

We’ve all used in-browser editors before. They can be nice to have. But at least now the option’s there—and if it’s ever needed, this one will be zero-jank, powerful, and fun.

Did this solve my “last updated” problem?

Only time will tell.

I might still SSH into the server and edit raw HTML with base Vim.
