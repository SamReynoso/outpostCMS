What This System Does

This application manages content fragments — including metadata, images, and potentially video — grouped into named projects. Each project is identified by a group and a project name, and content can be accessed, edited, or previewed via predictable URLs.

Core Concepts

Project:
A collection of metadata and assets (e.g. image, video).
Group:
An organizational prefix, often used for namespacing.
Fragment:
A discrete piece of data (e.g. canonical title, preview image).

Routes Overview

/projects/
list all projects
/projects/{group}/{project_name}/
view project details
/preview/{group}/{project_name}/
preview project output
/api/edit-metadata/
API endpoint to update metadata

Front-End Ingestion

To use the content in a front-end application, fetch fragments via the API or generate static representations from the preview route. Fragment structure is stable, and suitable for both SSR and client-side rendering.

Additional Notes

This system favors immutability and versioned updates. To publish changes, re-submit the project metadata and assets. Any published change should be considered final unless explicitly overwritten.
