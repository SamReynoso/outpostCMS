What This System Does

This application manages content fragments — including metadata, images, and optionally video — organized into named projects. Each project has two versions: a private workbook version for in-progress edits, and a canonical version that is optionally published and served through the public API.

Core Concepts

Project:
A named collection of metadata and assets (e.g., images, video), associated with a group.
Group:
A namespace or organizational prefix used to distinguish project ownership or scope.
Fragment:
A discrete unit of content (e.g., a title, image, or setting) managed independently within a project.
Workbook Version:
The editable draft state of a project. Changes here are not public until explicitly launched.
Canonical Version:
The published, immutable snapshot of a project served through the external API.

Versioning and Diff Previews

All changes to workbook content are version-controlled using Git. When viewing a project, the interface displays a live preview decorated with visual diff indicators to show what has changed since the last launch. This allows you to assess edits in context before promoting them to production.

While rollback is not yet implemented, it is on the near-term roadmap. Eventually, you’ll be able to revert a project’s canonical version to any previous state directly from the UI, with all changes tracked and annotated through Git.
