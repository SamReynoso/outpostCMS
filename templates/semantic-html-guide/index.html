Overview

  • Scope: Defines correct HTML usage for formatting articles that convey textual information.
  • Purpose: Enforce consistent and styling-agnostic formatting to maximize portability.
  • Goal: Articles should integrate cleanly into any environment with minimal CSS.

Preface: HTML offers flexibility, but this guide imposes strict structural rules to ensure technical content remains durable, readable, and portable—even without CSS.

Assumptions: Assumes content is placed inside an <article> element, and that the broader HTML structure (e.g., <html>, <body>) is already valid.

Guidance

Use the following guidelines to ensure your article is portable and accessible:

  • Use semantic HTML elements for structure and meaning.
  • Use sectioning elements to divide content meaningfully.
  • Use tables only for tabular data, never for layout.
  • Place all images within figure elements.
  • Use figcaption to describe the content of figures.
  • Avoid interactive and layout-oriented HTML elements in article content.

By following these guidelines, you can ensure that your articles are portable, accessible, and free of unnecessary styling dependencies.

Rationale

The goal of this document is to provide a set of guidelines for writing portable articles using semantic HTML. By following these guidelines, you can ensure that your articles are easy to read, understand, and maintain.

The guidelines are based on the principles of semantic HTML, which emphasizes the use of meaningful elements and attributes to convey the structure and meaning of content. By using semantic HTML, you can create articles that are accessible to a wide range of users and devices.

The guidelines also emphasize the importance of using sectioning elements to divide content meaningfully within the article. This helps to create a clear and logical structure for your articles, making them easier to read and understand.

Semantic HTML

This section focuses on the semantic use of HTML in document writing. It does not aim to serve as a reference to the HTML specification and only touches on topics deemed relevant to technical writing in the HTML format.

Preferred Tags

Use semantic elements for structure and meaning:

  • <section>, <aside>, <figure>, <blockquote>, <ul>, <ol>, <table>

Headings: <h1> through <h6>

  • Each article must begin with an <h1>.
  • An article must not contain more than one <h1>.
  • Do not skip heading levels.(e.g., do not jump from <h1> to <h3>).
  • Each sectioning element should include a heading reflecting its hierarchical level.

Article Sectioning

Use sectioning elements (<section>, <aside>) to divide content meaningfully within the article. <section> are a clear choice for main content given they are natively assigned the role region by default and are expected to have a header by document outliner tools, and screen readers.

Tables

Use <table> only for tabular data — never for layout.

  • Tables must include a caption unless inside a <figure> where a <figcaption> is preferred.
  • Non-primary tables (i.e., those not central to the section's message) should be wrapped in a <figure> element.

Images

  • Place all images within figure elements.

It is wise to place all images in the root of the article, not nested within section or aside elements. This ensures layout independence and consistent styling behavior.

Figures

Each <figure> must include a <figcaption> to describe its content. Use <figure> for content not part of the article’s primary flow, such as:

  • Images, diagrams, and illustrations
  • Secondary tables or supporting data

Conclusion

Writing with strict semantic HTML isn't just about portability and accessibility—it’s also about convenience and discipline. Over time, this approach improves not just your markup, but your productivity and communication as a whole.
